## 1. 目的と読者

Discord サーバー「ねっこ集会所」で開催する、ホロライブドリームスのミニゲーム
**ポカジャン** の大会案内を、URL 1本で伝えられるようにするためのページです。

Discord のテキストチャンネルに案内を流すと、あとから来た人が過去ログを遡らなければ
なりません。1枚のページにまとめておけば、リンクを貼るだけで済みます。

| 読者 | 想定 | 設計への影響 |
|---|---|---|
| 参加者 | Discord からスマホで開く人が大半 | スマホ幅を主、PCを従として作る |
| 更新者 | このリポジトリを直す人（＝あなた） | ビルド不要・文言はHTML直書き |

### 情報の見えかたについて

**リポジトリは Public です。** サイトの URL を知らなくても、GitHub から
ソースと過去の全履歴が読めます。**一度コミットした内容は、あとでサイトから
消しても履歴に残り続けます。**

`index.html` に `noindex` と `robots.txt` を置いて検索避けをしていますが、
**防げるのは「検索からの偶然の発見」だけ**です。URL を渡された人、GitHub から
辿る人には効きません。

そのため、**参加者名のように出したくない情報は最初から載せない**という判断が要ります。
BRACKET に表示名を出すかは、参加者が確定してから決めます。
（日時・ルール・応募方法は広めたい情報なので、公開されていて問題ありません）

## 3. ページ全体の構成

縦1枚のスクロールページです。上から順に読めば、参加までの判断ができる並びにしています。

| # | セクション | id | 役割（何を判断させるか） |
|---|---|---|---|
| — | ローディング | `.splash` | CSSだけで2秒ほど。開いた瞬間の印象づけ |
| — | ヘッダー | `.site-header` | 常時追従。スクロールで影が付く |
| 1 | HERO | `#top` | **いつ・どこで・何をやるか**を一目で。手札7枚に要点を集約 |
| — | 流れる帯 | `.marquee` | 区切りの装飾 |
| 2 | ABOUT | `#about` | **参加していいのか**の判断（未解放でも可・抽選で卓分け） |
| 3 | RULE | `#rule` | **ポカジャンを知らない人の最低限の予習**＋この大会独自のルール。点数計算などの詳細は外部の攻略サイトへ送る |
| 4 | FLOW | `#flow` | **当日どう動くか**を6ステップで |
| 5 | BRACKET | `#bracket` | **自分がどの卓か**と勝ち上がり。Googleスプレッドシートを読んで組み立てる（下記） |
| 6 | ENTRY | `#entry` | **応募の3ステップ**とフォームへのボタン |
| — | フッター | `.site-footer` | 非公式である旨の注記・問い合わせ先 |

RULE を ABOUT と FLOW の間に置いているのは、ポカジャン未経験者の参加を前提に
しているためです。「参加していい」と分かった直後に遊びかたを説明します。

### BRACKET だけ、文言をHTMLに持っていません

このサイトは「文言はすべて `index.html` に直書き」で作っていますが、
**トーナメント表だけは Googleスプレッドシートから読んでいます。**

**主催者が当日動けなくても、他の人が結果を反映できるようにするため**です。
スプレッドシートの「勝ち」欄に印を入れるだけで表が変わるので、
GitHubアカウントもPythonもパソコンも要りません。スマホで足ります。

読めなかったときは「当日をお楽しみに」の表示に戻るだけで、
**ページの他の部分は普通に動きます。**

> Googleのスプレッドシートは `Access-Control-Allow-Origin` を返さないため、
> ふつうの fetch では読めません（実測で確認）。制限を受けない JSONP を使っています。

**RULE には、点数計算や役ごとのコインの数字は載せません。** 自分で書くと維持できず、
間違ったまま残るためです（詳細設計書の章2-7）。代わりに RULE の**末尾**に、
実際のゲーム画面つきで解説している攻略サイトへの参考リンクを置いています。
末尾に置いているのは、大会独自ルールを読み飛ばして外部へ離脱させないためです。

## 4. 技術方針とその理由

**素の HTML / CSS / JavaScript のみ。ビルドもフレームワークも使いません。**

| 方針 | 理由 |
|---|---|
| ビルド不要（npm・バンドラなし） | `index.html` をダブルクリックすれば見える。環境構築でつまずかない |
| ファイルは3つだけ（HTML / CSS / JS） | どこに何があるか迷わない。全文検索で必ず見つかる |
| 文言はすべて HTML に直書き | JavaScript が動かなくても全内容が読める。テキストエディタで直せる |
| 読み込む外部リソースは Google Fonts のみ | 失敗しても端末標準のゴシックへフォールバックする。攻略サイトへの外部リンクは張っているが、表示には影響しない |
| パスはすべて相対 | GitHub Pages でもローカルでも zip 配布でも、設定なしで動く |
| `color-scheme: light` を固定 | ブラウザのダークモード強制による色反転事故を防ぐ |

### 壊れにくくするための3つの仕掛け

このページの設計上いちばん重要な部分です。

**(1) 画像は「読み込めたものだけ出す」**
画像を置く枠には `data-img-slot` を付け、初期状態を `hidden` にしています。
JavaScript が画像の読み込み成功を確認してから `hidden` を外すため、
**ファイルが無くても壊れた画像アイコンや空の枠は出ません。**
見出しごと消したい場合は `data-reveals` / `data-img-group` で連動させます。

**(2) `.js` と `.anim` の2段階クラス**
- `.js` … `<head>` のインラインスクリプトが付ける。**CSSだけで完結する演出**に使う
- `.anim` … `script.js` 自身が付ける。**JSが必要な演出（reveal）だけ**に使う

こう分けているので、`script.js` の読み込みに失敗しても
「要素が隠されたまま二度と出てこない」事故が起きません。
ローディングと配牌アニメは `.js` 側なので、CSSだけで最後まで動きます。

**(3) `prefers-reduced-motion` への対応**
端末が「視差効果を減らす」設定になっている場合、ローディング・配牌・花びら・
流れる帯・スクロール演出・壁紙の出入り・ねっ子の動き・**背景の幕**をすべて止めて
静止表示にします。幕は「開かずに残る」と本文が読めなくなるため、完全に非表示にします。

## 5. デザイン方針

- **モチーフは「花札」と「手札」。** 大会情報を7枚の札として扇状に並べ、
  読み込み後に配られるように出します。装飾（花びら・星・ねっこの芽）は
  すべて自作の SVG シンボルです。
- **色は桃鈴ねねのイメージカラーである桃色を主役に。** 純白は使わず、
  桃みのあるオフホワイト `#FFF7F3` を地にしています。色は
  すべて `:root` のトークンにまとめてあり、そこだけ変えれば全体の色が変わります。
- **本文のコントラストは 4.5:1 以上を確保。** 本文は約13:1、補足は約6:1 です。
  金色（`--gold`）は面と縁にだけ使い、文字色には使いません（`--gold-ink` を使う）。
- **見出しは金→白→桃の三重の縁取り。** 賑やかな背景の上でも読めるようにするためです。
- **ブランドマークは 🍑🥟。** 桃鈴ねねのファンマークで、Unicode の絵文字なので
  公式素材の転載になりません。
- 「ねっこの芽」は、ファンの総称「ねっこ」＝「根っこ」の語感から起こした
  **このサイト独自のシンボル**です。公式マスコットを模したものではありません。

## 7. 動作環境・公開方法・ページの重さ

**動作環境** — Chrome / Edge / Firefox / Safari の現行版。
IntersectionObserver 非対応の古いブラウザでは、スクロール演出なしで全内容が表示されます。

**公開方法**（まだ公開していません）

- **GitHub Pages** — リポジトリに push し、Settings → Pages でブランチを指定するだけ。
  パスはすべて相対なので追加設定は不要です
- **ファイルを直接渡す** — フォルダごと zip にすれば、`index.html` を開くだけで見られます

**ページの重さ** — 初回表示でおよそ 1.2MB（画像 373KB ／ フォント約 750KB ／
HTML・CSS・JS 約 60KB）。大半は Google Fonts の日本語フォントです。
2回目以降はブラウザのキャッシュが効きます。

## 8. あえてやらないと決めたこと

将来「こうしたほうがいいのでは」と思ったときに、
**一度は見送った判断である**ことを思い出すための一覧です。

| やらないこと | 理由 |
|---|---|
| CMS化・管理画面 | 年に数回の更新に管理画面は過剰。テキストエディタで足りる |
| ビルドツール（Vite / webpack など）の導入 | ファイル3つの規模では、環境構築のコストのほうが大きい |
| フレームワーク（React など） | 同上。素のHTMLのほうが誰でも直せる |
| JavaScript による文言の流し込み | JSが死んだときに何も読めなくなる。SEOにも不利 |
| 参加者一覧・トーナメント表の動的表示 | 当日 Discord 上で案内するため不要 |
| フォームの自作 | Google フォームで足りる。個人情報を自前で持たない |
| ダークモード対応 | 桃色を主役にした配色が崩れる。`color-scheme: light` で固定 |
